# Compliance corpus — JSON

Generated by [`pdf_to_chromadb.py`](../pdf_to_chromadb.py) from the source PDFs. **Do not edit
by hand** — rerun `python pdf_to_chromadb.py chunk` instead, so every file here is
reproducible from the PDFs.

**27 documents · 25 frameworks · 2,816 sections · 4,299 chunks**

```
compliance-corpus-json/            (data/ links here)
├── all_chunks.json                ← every chunk. pdf_to_chromadb.py embed indexes this.
├── index.json                     ← counts per framework
├── qa_report.json                 ← per-document extraction and structure stats
├── validation.json                ← invariant checks (ids unique, ≤512 tokens, …)
└── frameworks/<sector>/<FRAMEWORK_ID>/
    ├── metadata.json              ← HAND-WRITTEN input: name, regulator, dates, URL
    ├── <DOC>.chunks.json          ← that document's chunks
    └── <DOC>.document.json        ← whole sections + how the PDF was parsed
```

`metadata.json` is the only input here. Everything else is output.

Two frameworks have two PDFs each (`PCI_DSS_V4`, `SEBI_CYBERSECURITY_FRAMEWORK_2024`);
the second document's ids carry its PDF stem: `PCI_DSS_V4__PCI_PTS_POI_SRs_v7.0_supplementary-0001-c01`.

## A chunk

| Field | Meaning |
| --- | --- |
| `embed_text` | **Embed this.** `[framework \| regulator \| date]` + breadcrumb + `text` |
| `text` | **Show this.** The clause itself |
| `breadcrumb` | `Framework > Chapter > Section` — where the clause sits |
| `section_number`, `section_title`, `chapter`, `section_path` | Structure from the PDF's own headings |
| `page_start`, `page_end` | Pages in the source PDF, for citations |
| `part_index`, `part_total` | Position when a long section was split |
| `token_estimate` | Real `cl100k_base` token count of `embed_text` (≤ 512) |

## How it was built

Structure-aware chunking: one chunk per section, article or clause, split
further only past 512 tokens. Scanned PDFs (all SEBI documents, the Consumer
Protection Rules) were read with Tesseract OCR. See the docstring at the top of
`pdf_to_chromadb.py` for the full method, and `qa_report.json` for what each document
yielded (heading style detected, OCR pages, tables, lines removed as headers,
footers, footnotes and contents pages).
